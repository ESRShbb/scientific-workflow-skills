# Validation and capability boundaries

Methods-only package: no executable or synthetic success count. Static packaging/link checks do not prove visual judgement.

## Cases

1. Request three independent figures from a multipanel source: preserve separate scope; do not invent one A/B/C composite.
2. A bubble plot uses area for counts but another panel uses a different statistic: share typography without changing mappings.
3. A source blot has ambiguous lane labels: mark scientific correspondence unresolved; do not guess to align it.
4. An attractive docking panel is supplied: keep computational model provenance and do not call it an experimental structure.
5. A journal specifies fonts unlike an old reference: use the actual destination and check final-size readability.
6. Actual external-project figures: inspect final saved renders at whole/panel/detail/use-size views. Independent behavioural and visual validation deferred.

No test on a single host proves another computer, OS, software version or license is compatible. Record the actual environment and separate static, native, visual and scientific conclusions. Local helper success must not be reported as full workflow validation.

## Revision 0.2.0 focused checks

With authoritative values, bind category/value/graphic/label and propose one self-consistent minimal correction. A single summary row does not establish n=1. Classify scientific corrections, optional style and missing evidence separately.

Treat scripts added in 0.2.0 as target-installation probes; consult their actual task logs. Package tests do not certify arbitrary native inputs or other computers.
